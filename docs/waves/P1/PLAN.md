## 交付目标

1. 在既有云服务器部署真实 SuperAgent/DSH 新助手，沿用已核实的公网访问入口，完成 Linux、TLS、登录、反代、持久化、重启与备份恢复验收。
2. 迁移旧助手的实际工作台数据，重点保证 cc 建议及其完整生命周期不遗漏，最终一致性对账通过后再切流。旧助手成功退役，停止后续功能维护；保留有限恢复资产，不维持双系统日常开发。
3. 原有每日维护任务接替到新仓库、新生产权威和私有去重登记，维持北京时间01:00、已有通知/目标及安全边界，只运行一个有效 Leader。
4. 更新公开项目说明、旧项目退役提示及个人 GitHub 主页。文案依据实际发布阶段，不提前宣称 P1 或生产验收完成。
5. 在同一 P1 内分三段交付 SuperAgent 用户价值：真实责任与人工行动展示；有明确授权与期限的库存持续跟进；单条内部复核规则 observe 验证后进入窄范围 auto。

可写新仓库准备材料及仓库外私有准备快照，可只读核查本机既有资料和 GitHub/automation 元数据。当前不连云端，不运行部署/迁移，不改产品代码、不改旧项目/定时任务/个人主页、不发起模型调用。P0 历史禁云说明属于当时授权；P1 生产执行须收到新的启动消息才生效。

## 失败与退役

切流前失败：新候选隔离，旧权威未改，可恢复旧入口写入。新入口已接受写入后失败：先冻结新写入，保存新增建议、删除/撤销及用量；优先前滚，受控反向迁移验证后才可回旧库。禁止直接指向过期旧快照。新旧自动维护不得同时写；旧代码和状态资产保留至验收及一次恢复演练完成后形成保留清单，无需删除旧仓库或历史备份。
