# P1 · 投递、评估和业务结果分别记账

2026-11-05，根任务P1-CLOUD-SUCCESSOR。同类事件身份问题累计保留；以下是重新诊断后的决定，不通过重命名任务清零。

## 已观察问题

原生Source已接收事件，不代表模型已完成评估或创建业务草稿。观察候选投递后，若评估被中断，再关闭/重开同一规则，旧候选的策略修订已失效，但仅按规则ID/模式/风险摘要去重又阻止新策略产生候选。这与人工要求重新评估的事实不一致。

另一个实际验收中，已完成跟进且已有草稿的风险被真实模型正确忽略；正向观察验收必须选择尚未处理的新对象，不能要求模型重复工作。测试脚本时钟排序、恢复时原请求CAS和临近期限的夹具控制均单独记录，不冒称产品Red。

## 决定

- 事件身份含当前规则修订，当前修订内重启/重投仍幂等；新明确策略允许新的观察评估。
- markDelivered只记录原生入站投递。只有实际Engine Decision接受auto候选，才由可信原生适配器记下已接单风险窗口；领域层不根据模型文本、HTTP声明或投递状态推测接受。
- 适配器从真实Decision及其Trigger/event关联同步结果，在修改规则前和扫描前执行。snapshot保持纯读；领域不依赖Runtime。
- 已实际接受的auto风险窗口跨规则关闭/重开也不能重复创建工单。ignored/would_accept不是业务草稿交付，不能作为已交付去重。
- 原生会话读取历史与当前写入授权分开；可以读同scope非删除历史，但写草稿须重读最新风险。真实人工等待阶段阻止自动输入。
- 人工对跟进工单的后续回答仍携带原授权/对象的来源父链。删除原授权或事实时，后续回答派生的草稿也须闭包删除，不能只终止Session而留下派生内容。

验证覆盖规则修订重评、投递但未接受、已接受窗口去重、重启、历史读取/删除、人工等待和后续人工答复的派生隐私闭包。所有收费/未知用量保留原账本，不通过测试恢复退款或清零。
