## 先后与并行

1. R0 原生门槛：固定SuperAgent源码/许可证和DSH依赖候选，实际验证Windows、Runtime/Engine/Source/Session、UI加载、认证接缝、运营工具隔离及零重试。补丁对应SP01–08；失败先有限诊断，不假称可用。
2. 业务迁移：在冻结应用契约下，迁移纯计算/状态/存储/学习规则，TDD修复旧耦合；可与R0并行，因为不依赖未经验证的宿主API。
3. UI与工具：R0原生客户端入口确认后迁移全部中文页面与模型工具/Provider，共用应用服务；不扩大模型写权限。
4. 集成：可信Source准入、稳定operationId、全入口认证、模型账本、工单与业务状态分离、取消/重启/隐私/协调恢复。
5. 独立审核与验收：规则测试、原生契约、故障、实际浏览器、必要真实模型和合成旧格式副本迁移；逐项59矩阵填证据，修复复验。
6. 本机交付：可重复安装/构建/启动说明、短中文说明、精确提交/产物/上游/锁文件、真实用量和已知限制；推送新仓库。未通过强制项则partial/blocked，不宣称完成。

## 角色与所有权

Leader：共享规格/DTO、依赖锁、host/source/auth/模型集成、状态/证据、集成与最终报告。

p0_backend：packages/business、tests/business；迁移全部领域/学习/持久保障，拆分Command/Query和任务/学习反向依赖。

p0_native：vendor/superagent、profiles、tests/native；真实底座适配与契约探针，保留上游core，不接触业务源码。

p0_frontend：packages/client、tests/client；全部中文原生页面及对话/工单交互，只用共享DTO和冻结HTTP契约。

p0_review：独立只读规格/代码/证据审核；按可用槽位在初期接缝和集成候选阶段运行。所有写者独立codex/分支和仓库外worktree；Leader先冻结自包含任务包再派发，不重用旧Agent自称测试结果。

## 修复与停止

累计根因修复计数不清零；两次定向修复后先重新诊断及记录决定，不自动换波次。遇必要外部输入先推进独立工作，只有无可推进任务时说明具体阻碍；不以普通阶段结束要求再次审批。用户停止、明确约束、非授权操作均停止相应动作。
