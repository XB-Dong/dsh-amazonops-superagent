# 数据、迁移与恢复设计

v0.1｜仅设计；未读取或迁移生产数据。

## 单一所有者

| 数据 | 所有者 | 规则 |
| --- | --- | --- |
| 业务任务、报表、预测、分配、笔记、反馈、事实、Skill、命令回执/outbox | cc 业务存储服务，Node SQLite | 短事务、WAL、scope、CAS、唯一幂等键；保留精确值与来源 |
| Trigger/Thread/Mandate/Ticket/Assignment、投递与编排 Effects | 上游 SuperAgent Store/Engine | 不由业务 SQL 越权修改；按其事务和恢复语义 |
| Session 事件/压缩/原生流式结算 | DSH Persistence | 通过受支持 API 读写，不直接改 JSONL，不复制另一份对话权威 |
| 业务文件、导出、备份、许可的 Skill 正文 | 受控本机文件存储 | 路径、scope、hash、引用；仓库外，禁止链接逃逸 |
| 模型请求账本、删除/撤销与禁恢复 lineage | 独立持久政策服务 | 恢复不能退还用量或复活来源；最小不含原文标记 |

业务事件与命令回执在同一业务库事务提交，通过 outbox 与稳定 Trigger ID 桥接编排库。业务库与编排库之间不承诺全局事务；设计崩溃点、重放和对账，最终一次业务效果。

## 迁移分层

P0 本机验收只用合成数据或新建的本机旧格式夹具。按旧 schema 构建副本，保留原 ID、scope、revision、UTC 日期、确认状态、来源及撤销关系；检查实体计数之外还要逐字段、引用闭包和输出行为比较。旧文件 hash、数据版本及转换器版本进入证据。

旧会话格式可否按原生 provider 迁移须真实验证；保留 sessionId 映射。若不能无损继续，不伪造历史为新消息；提供只读历史与新会话引用策略，并将是否满足完整复现交由规格审核。真实数据源或生产切换不由本地夹具通过自动授权。

## 协调备份与隔离恢复

冻结接收新 Command/Source → 等待在途业务事务和模型结算/保留未知账 → 停/flush 原生执行器与持久化 → 使用 SQLite backup API 分别备份业务、编排和用量库 → 备份会话、引用文件和最新隐私账本 → 生成逐文件 hash/字节/版本清单。

仅恢复到空隔离目录；校验路径、符号链接、hash、schema、SQLite integrity 与引用。合并当前用量账本只增不退，先重放最新删除/撤销/Session denylist，再开放 Source/工具和查询。离线恢复测试证明来源、旧 Session、待投递事件和备份均不能恢复被删除业务或撤销经验。

代码回退与数据恢复分别设计。局部失败的恢复目录不得接入运行入口；数据转换不覆盖原输入。新旧系统禁止同时写一份业务库；未来正式迁移若获授权，需单独停写/校验/回退方案，不属于本轮。
