# SDD / TDD 与整套 P0 验收设计

此文保留准备时的验收设计；用户“启动”后实际结果以 [验收矩阵](acceptance.json)和 P0 执行报告为准。准备检查始终不算产品功能测试。

## 规格追踪

需求 → 功能边界 → domain/tools/security/data 契约 v0.1 → [机器验收矩阵](acceptance.json) → 未来实现 SHA/环境/命令/输出/证据 → 审核处置。多段 CC-TASK-COPY-001 必须作为完整 ID 识别。

验收矩阵覆盖全部 20 个 P0 需求组，不以页面数量或单测数量代替业务通过。CC-CUSTOMER-001 和其他未交付候选单列排除。旧 34 个测试源文件可借行为断言，旧通过结果不继承。

## 测试层次

1. 领域规则：计算、时区、状态、金额、幂等/CAS、来源与删除。先写目标行为失败，再实现并通过；保留实际 Red/Green 和失败原因。
2. 原生契约：真正加载上游适配 Runtime、Engine、Store、DSH Agent/工具/Provider；不能用完全 mock 掉宿主的单测替代。
3. 故障集成：outbox 崩溃窗口、重复事件/补充/撤回、取消迟到回调、重启/恢复、跨 scope、未授权工具和入口绕行。
4. 本机浏览器：13 个主入口加登录/设置的完整行为、中文可读性、持久化、日期/用时输入、复制确认、模型离线仍可操作；仅实际操作才记录浏览器通过。
5. 合成端到端：活动四阶段、CSV→预测→库存→共享分配→发货、广告→建议→导出、成功任务→经验→复用→撤销，贯穿新宿主。
6. 必要真实模型：仅在后续 P0 执行授权与本机测试账户准备后，覆盖原生接单/工具/完成回复、经验/恢复代表闭环；所有角色调用记账，无人为累计测试上限、零自动重试。当前不调用。
7. 备份/旧格式副本迁移：不接触生产，验证多库/会话/账本一致与删除不复活。云端验收不是本机 P0 的默认门槛。

## 证据要求

每条结果绑定 caseId、需求、规格、精确实现/上游 SHA、依赖锁、操作系统/Node/浏览器、命令/步骤、时间、退出码、实际结果和原始证据位置。原始合成运行证据保存在仓库外，Git 只留脱敏索引和 hash。模型自称成功、静态截图、伪事件或旧平台运行不能替代实际状态核验。

预计接口不可用导致安装失败只记录为环境/兼容性失败，不冒称 TDD Red。修复后只对影响范围复验，通过后停止无用重复测试。独立审核从规格阶段开始，产品作者自查不算独立验收。

## P0 完成定义

真实原生 SuperAgent 链路运行；全部旧已交付功能在新页面/工具复现；全部强制 case 实际通过；权限/重复/冲突/取消/删除/恢复负向无未关阻断；必要浏览器和模型闭环有证据；本机打包运行及中文说明可用；旧云服务及自动任务无变更。

只要其中任一强制项未通过，P0 为 partial/blocked，不能将它留给下一波后声称 P0 完成。
