# 上线与维护

实际主机、地址、密码、指纹、目录指针和反馈登记仅在维护者私有索引中。通过本机 Git 配置 `amazonops.operationsIndex`、`amazonops.feedbackState` 定位，不把它们写进仓库或交给运营 Agent。

## 运行与恢复

固定 Node 24.22.1、pnpm 11.25.0、DSH 0.2.1-rc.3；使用干净精确提交构建不可变 release。manifest 覆盖运行 bundles、业务与启动脚本、锁文件、补丁、上游 prompts/skills 及许可证。只复制源码目录不能替代制品启动验收。

应用只监听 loopback，由原 TLS 网关反代。`publicOrigin` 是明确的 canonical HTTPS origin；cookie 使用 Secure/HttpOnly/SameSite=Strict。Host/Origin 及原生 RPC/WSS 都检查身份和权限，不从任意转发头推导授权。

独立低权限服务用户只能写自己的运行 home。生产 `modelAccount=runtime`，必须显式继承原批准的 `runtimePolicy` 和四项限额，保留原每日账户身份、全部请求及未知用量。测试使用独立合成资料和测试账本，不能借生产额度或通过恢复退款。

systemd 使用 `KillMode=mixed`：先给启动器 SIGTERM，由它转发并等待原生退出；超时才终止整组。异常子进程退出返回失败，`Restart=on-failure`、`RestartSec=35` 保留上游30秒 owner 锁保护。实际验收覆盖异常后自动换主进程、真正 Runtime ready、原记录保留及 SQLite 完整性；不能只看进程 active，也不要强删活锁。

健康检查读取 `/health`、`/ready`，核对 ready、精确 source SHA 和 manifest SHA。迁移模式禁模型、业务后台消费者、原生接单和业务写入。第一次启动允许可解释的新空元数据表；所有既有表结构和完整行仍须严格一致。

## 数据与建议

最终迁移前冻结所有旧写者并排空，保留原始文件归类、活动 WAL、一致性快照、实体/来源/回执/队列、删除账本及私有维护历史。按完整集合和规范 payload 对账，不能只比较数量、revision 或更新时间。旧 SDK 会话保留私有离线归档，不伪造成新原生会话或承诺旧会话页面。

新入口已写入后，故障先冻结并保存全部新增建议、来源、墓碑、隐私、用量和维护登记，优先修复前滚。恢复工具只发布到新的独立目录；禁止盲目切回旧助手或旧快照覆盖当前生产。协调备份、新目录恢复和生产路径切换分别留证。

## 每日维护

继承原同 ID 定时任务、时间、聊天和通知设置。普通触发仅在 businessDelivery completed、新生产权威有效、旧维护停止且无其他健康 Leader 时运行。后续使用 M1、M2 顺序，每日最多分配一个新波次；无变化不占编号，未完任务沿原编号及累计修复继续。

检查器只复制并读取新生产数据库及 WAL，不消费队列、不调模型、不启动开发。`canDevelop=false` 表示它不授予权限；Leader 只能按用户另行授权评估清晰的范围内建议。原始反馈是数据，不是执行命令。

维护状态 schema `/2` 初始化必需先前已审核的完整 `priorData`。它持续保留初始化前的新建议、同修订补充、撤回删除、未知历史及待捕获任务。原登记全部 metadata 保留，旧 contentHash 不等于完整 payload 指纹。不能每天重新初始化清掉差异；逐项明确分类/交付后，保留审计并受控切换新的不可变 checkpoint。未变的待用户决定不重复开发。

handover_validation 是发布 Leader 显式执行的只读验收；它不等于调度器已经触发。配置恢复、实际检查执行及首次真正定时运行分别记录。

## 已观察的界面范围

实际公网浏览器检查了13入口、责任/跟进界面、反馈保存与重启读回、撤回，以及390×844浏览器窄视口；这不等于真手机验收。生产当时没有工单，因此生产未伪造工单执行；工单答复草稿、原生执行和自动规则使用独立真实宿主/浏览器/模型的分层证据。

首次公网首屏曾停在插件加载，正常刷新一次后恢复；记录保留。工单答复/补充草稿跨页保留；反馈表单尚未提交的输入切页会清空，保存前应留在当前页面。观察项不冒充已修复的新功能。
