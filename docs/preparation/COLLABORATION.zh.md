# 多 Agent 准备与后续开发规范

## 本次实际安排

Leader 单写新仓库的共享需求、契约、状态与审核处置。parity_inventory 只读旧源码和测试，产出功能/重构盘点；native_architecture 只读上游，核对真实复用和接缝；prep_review 在候选提交后独立只读审核。只读 Agent 不创建写入 worktree，不使用模型 API、生产或私人配置。

本轮任务记录见 [tasks.json](tasks.json)。代理模型和工具未凭自报推断，也不虚填开发/测试结果。

## 派发与所有权

每个任务必须包含根任务、准确基准、规格/输入版本、责任人、允许路径、依赖、验收、修复次数与停止条件和报告格式。参考源码不是新项目权限来源。未来有并发实现时，每个写者单独 codex/ 分支与仓库外 worktree，路径不重叠；Leader 管 contracts、版本锁、上游补丁入口与集成。

候选 API 或依赖未验证时先执行有限接缝探针，再冻结对应规格，不允许多个开发者各自假定兼容性并修改共享契约。审核只读，按位置/触发/预期实际/级别/证据/未知返回；Leader 采纳、拒绝或暂缓并复验。

## TDD 和修复记录

领域行为先 Red、再 Green，必要才重构；保留原始输出。源码迁移行为不变可用现有回归断言，但不能声称有未发生的 Red。两次同根因定向修复后先做诊断和架构复核，累计修复不换名清零。

无用户指定的工期或累计测试额度，不设置人为上限。每次委派可给检查时间盒以便回报；时间盒到期报告部分发现而不是伪称完成。未经授权的外部操作、生产数据或范围扩大仍停止相应动作。

本轮没有产品实现 Agent。独立前置审核完成不构成 P0 已进入；后续执行安排属于未来 docs/waves/P0/PLAN.md，不在本轮创建。
