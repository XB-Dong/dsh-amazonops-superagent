# P0 执行计划前的就绪门槛

用户已定义 P0 交付终点：完整重构 ccagent 并通过功能测试。本文不是执行计划，也不派发实现任务。

## 本轮必须完成

- 新本机目录、独立 Git 历史及指定 GitHub 仓库；默认私有、无凭据和旧业务数据。
- 旧系统功能、模型工具及候选边界完整盘点；现有全部已交付能力纳入 P0。
- 真实 SuperAgent/DSH 架构、模块归属及需要受控适配的接缝有来源证据。
- 业务/编排/工具/权限/数据与恢复契约、完整验收矩阵和多 Agent/TDD 规范。
- 独立只读前置审核，阻断发现修正并复验；准备检查通过，GitHub 内容同步并回读。
- 明确当前所有产品运行、兼容性和功能验收为 not_run，未接触云或旧自动任务。

## 进入 P0 计划时必须解决的设计输入

精确依赖图、所有补丁允许路径和维护者、全入口鉴权接缝、原生 Windows 兼容性、实际 LLM 与测试配置不能假定已通过。它们已经识别为 P0 的首批技术门槛，可在后续执行计划中编排验证；不能在准备阶段预填完成。

未来 P0 计划需要在准确候选提交上冻结执行任务包、所有者、依赖、验收和修复条件。P0 内部可按技术依赖分阶段推进，最终仍需全部业务和横切验收完成。本轮不创建 PLAN.md，不安装依赖、不构建/启动应用、不调用模型。

状态以 [state.json](state.json) 为准。前置完成只表示 ready_to_plan，不表示 frozen/executing/completed 的产品波次。
